# MODBUS模块配置文件使用文档

## 概述

MODBUS模块是IOUI框架下的设备驱动模块，支持Modbus RTU和Modbus TCP两种通信协议。该模块能够读取数字量输入(DI)、模拟量输入(AI)，并支持数字量输出(DO)和寄存器写入功能。

**主要特性**：
- 🔌 支持Modbus RTU（串口）和Modbus TCP（网络）双协议
- 📊 支持多种数据类型：uint16, int16, uint32, int32, float32, fixed16_16
- 🔄 支持多字节序：AB(大端), BA(小端)
- 🎯 支持编码器专用格式：Q16.16固定点数
- 🚀 纯主动轮询模式，高效稳定
- 🔒 连接共享和线程安全设计
- 🎯 灵活的通道映射配置
- ✨ **智能默认值，90%场景只需2参数** 🎉
- 🔄 **自动断线重连，长期稳定运行** 🛡️

---

## 配置文件结构

配置文件为INI格式，位于`Config\MODBUS\config.ini`。

**基本结构**：
- `[default]` - 默认配置参数（可选）
- `[device_N]` - 具体设备配置（N为设备索引号，从1开始）

**示例结构**：
```ini
# 默认配置（可选）
[default]
poll_interval_ms=100
command_interval_ms=10

# 设备1配置
[device_1]
driver=modbus_tcp
ip=192.168.1.100
# ... 其他配置

# 设备2配置
[device_2]
driver=modbus_rtu
port=1
# ... 其他配置
```

## 配置参数详解

### 1. 连接参数

#### 串口通信参数（Modbus RTU）
```ini
# 数据位 (默认: 8)
data_bit=8

# 停止位 (默认: 1) 
stop_bit=1

# 校验位 (默认: N)
# N-无校验, E-偶校验, O-奇校验
parity=N

# 波特率 (默认: 9600)
baud_rate=9600
```

#### 网络通信参数（Modbus TCP）
```ini
# IP地址
ip=192.168.1.100

# TCP端口号 (默认: 502)
port=502
```

#### 通用Modbus参数
```ini
# 从机地址 (默认: 1)
slave_addr=1

# 命令超时时间，单位ms (默认: 100)
timeout_ms=100

# 指令失败重试等待时间，单位ms (默认: 20)
retry_wait_ms=20
```

---

### 2. 轮询时序参数

```ini
# 轮询间隔(ms) - 每轮读取完成后的等待时间 (默认: 100)
# 控制数据刷新频率，值越小刷新率越高
# 快速响应场景：10-50ms
# 普通场景：100-200ms
# 慢速设备：500-1000ms
poll_interval_ms=100

# 命令间隔(ms) - 连续读取命令之间的间隔 (默认: 10)
# 防止设备响应不过来，值越大越稳定但刷新率越低
# 高速设备：5-10ms
# 普通设备：10-20ms
# 慢速设备：50-100ms
command_interval_ms=10

# 断线检测阈值 - 连续失败多少次判定为断线 (默认: 3)
# 设置太小(1-2)：偶尔丢包就判定断线，误判率高
# 设置太大(>10)：真正断线时检测慢，恢复时间长
# 推荐值：2-5次
# 计算公式：检测时间 ≈ max_consecutive_failures × (timeout_ms + poll_interval_ms)
# 示例：3次 × (100ms + 100ms) = 600ms 内检测到断线
max_consecutive_failures=3
```

**性能计算示例**：
```
场景A：DI + AI单通道
poll_interval_ms=100, command_interval_ms=10
轮询周期 ≈ 100 + 10 + 10 = 120ms
刷新率 ≈ 8.3Hz

场景B：快速响应
poll_interval_ms=10, command_interval_ms=5
轮询周期 ≈ 10 + 5 + 10 = 25ms
刷新率 ≈ 40Hz
```

**断线检测时间计算**：
```
默认配置：max_consecutive_failures=3, timeout_ms=100, poll_interval_ms=100
断线检测时间 ≈ 3 × (100 + 100) = 600ms

快速检测：max_consecutive_failures=2, timeout_ms=50, poll_interval_ms=50
断线检测时间 ≈ 2 × (50 + 50) = 200ms

稳定配置：max_consecutive_failures=5, timeout_ms=200, poll_interval_ms=100
断线检测时间 ≈ 5 × (200 + 100) = 1500ms
```

### 3. 数字量输入(DI)配置

```ini
# DI功能码 (默认: 0x02)
# 0x01 - 读取线圈状态(可读写)
# 0x02 - 读取离散输入状态(只读)
di_func=0x02

# DI通道数量，16进制格式 (默认: 0x0000)
di_num=0x0010
```

### 4. 模拟量输入(AI)配置 ✨

MODBUS模块采用**统一的通道格式配置**，支持智能默认值，让配置更简洁。

#### 配置格式

```ini
# 格式: ai_channel = 地址, 数据类型[, 缩放系数][, 字节序][, 功能码]
# 默认值: 缩放系数=1.0, 字节序=AB(大端), 功能码=ai_func
```

**参数说明**：

| 位置 | 参数 | 必需性 | 默认值 | 说明 |
|------|------|--------|--------|------|
| 1 | 地址 | ✅ 必需 | - | 寄存器起始地址（十六进制，如0x0000） |
| 2 | 数据类型 | ✅ 必需 | - | uint16, int16, uint32, int32, float32, fixed16_16 |
| 3 | 缩放系数 | ⭕ 可选 | 1.0 | 实际值 = 寄存器值 × 缩放系数 |
| 4 | 字节序 | ⭕ 可选 | AB | AB(大端), BA(小端) - 仅对32位数据有效 |
| 5 | 功能码 | ⭕ 可选 | ai_func | 0x03(保持寄存器), 0x04(输入寄存器) |

**配置复杂度梯度**（从简单到复杂）：

| Level | 场景 | 示例 | 简化率 |
|-------|------|------|--------|
| **Level 1** | 最简配置（90%场景） | `0x0000, uint16` | **-60%** ✨ |
| **Level 2** | 需要缩放（40%场景） | `0x0000, int16, 0.1` | **-40%** ✨ |
| **Level 3** | 指定字节序（15%场景） | `0x1000, float32, 1.0, BA` | **-20%** ✨ |
| **Level 4** | 完整配置（5%场景） | `0x1000, float32, 0.01, BA, 0x03` | 0% |

#### 单通道配置

使用 `ai_channel` 配置单个AI通道（等同于 `ai_channel_0`）：

```ini
# AI功能码（默认）
ai_func=0x04

# 示例1：最简配置 - 读取uint16（默认缩放1.0，默认大端序）
ai_channel = 0x0000, uint16

# 示例2：温度传感器 - int16类型，缩放0.1倍
ai_channel = 0x0000, int16, 0.1

# 示例3：编码器 - 32位整数，小端序，缩放0.001倍
ai_channel = 0x1000, int32, 0.001, BA

# 示例4：浮点温度 - float32，小端序
ai_channel = 0x0200, float32, 1.0, BA

# 示例5：编码器位移 - Q16.16固定点数（自动除以65536）
ai_channel = 0x0300, fixed16_16

# 示例6：完整配置 - 指定所有参数
ai_channel = 0x1000, float32, 0.01, BA, 0x03
```

#### 多通道配置

使用 `ai_channel_N` 配置多个AI通道：

```ini
# 通道0：状态字（最简配置）
ai_channel_0 = 0x0000, uint16

# 通道1：温度（需要缩放）
ai_channel_1 = 0x0010, int16, 0.1

# 通道2：位置（32位，小端序，缩放）
ai_channel_2 = 0x0100, uint32, 0.001, BA

# 通道3：速度（浮点，小端序）
ai_channel_3 = 0x0200, float32, 1.0, BA

# 通道5：跳过通道4，直接配置通道5
ai_channel_5 = 0x0300, int16, 0.01
```

**多通道配置说明**：
- `ai_channel` 等同于 `ai_channel_0`
- 如果同时配置了 `ai_channel` 和 `ai_channel_0`，以 `ai_channel_0` 为准
- 每个通道独立配置地址、数据类型、缩放系数、字节序、功能码
- 支持地址不连续，通道索引可以跳跃（如0, 1, 2, 5, 10...）
- 通道间自动添加命令间隔，避免设备响应不过来

### 5. 数据类型说明

| 类型 | 寄存器数 | 数值范围 | 字节序 | 说明 |
|------|---------|---------|--------|------|
| **uint16** | 1 | 0 ~ 65535 | - | 无符号16位整数 |
| **int16** | 1 | -32768 ~ 32767 | - | 有符号16位整数 |
| **uint32** | 2 | 0 ~ 4,294,967,295 | AB/BA | 无符号32位整数 |
| **int32** | 2 | -2,147,483,648 ~ 2,147,483,647 | AB/BA | 有符号32位整数 |
| **float32** | 2 | IEEE 754 | AB/BA | 32位浮点数 |
| **fixed16_16** | 2 | ±32767.999 | AB/BA | Q16.16固定点数（编码器专用）⭐ |

**字节序示例**：
```
寄存器值：[0x1234, 0x5678]

AB (大端序)：0x12345678
BA (小端序)：0x78563412
```

**fixed16_16 特殊说明** ⭐：
```
Q16.16 固定点数格式:
[符号位1][整数15位][小数16位]

示例值:
- 0x0007ADA7 = 7.678 (正数)
- 0x8007ADA7 = -7.678 (负数)
- 0x00010000 = 1.0
- 0x00008000 = 0.5

解算方式: value / 65536
适用设备: 海德汉编码器、多摩川编码器、部分位移传感器

配置示例:
ai_channel = 0x0000, fixed16_16           # 最简配置
ai_channel = 0x0000, fixed16_16, 1000.0   # mm转μm (保留精度)
ai_channel = 0x0000, fixed16_16, 1.0, BA  # 小端序设备
```

**重要**：所有AI数据最终会映射到`short`类型(`-32768~32767`)，超出范围的值会被自动限制。建议使用缩放系数将数据缩放到合适范围。

### 6. 数字量输出(DO)配置

```ini
# 写寄存器地址偏移，16进制格式 (默认: 0x0000)
# 实际写入地址 = 通道号 + do_addr
do_addr=0x0000

# 默认DO功能码 (默认: 5)
# 当通道250的值为0时使用此功能码
# 5 - 写单个线圈
# 6 - 写单个寄存器
do_func=5
```

**DO写入说明**：
- 通道0-239：普通DO通道
- 通道240-242：特殊命令通道
  - 240：功能码(1=写线圈5, 2=写寄存器6)
  - 241：写入地址
  - 242：写入数据
- 通道250：写入功能码覆盖
  - 为0时使用`do_func`配置
  - 非0时使用该值作为功能码

## 数据读取和写入

### 输入数据读取

#### 数字量输入(DI)
- 支持功能码01(读线圈)和02(读离散输入)
- 数据以位为单位，每个通道对应一个位状态
- 通过`GetDeviceDI`函数获取
- 后台线程自动轮询更新

#### 模拟量输入(AI)
- 支持功能码03(读保持寄存器)和04(读输入寄存器)
- 支持5种数据类型和2种字节序
- 支持浮点数缩放
- 自动溢出保护（限制在-32768~32767）
- 通过`GetDeviceAD`函数获取
- 后台线程自动轮询更新

### 输出数据写入

#### 数字量输出(DO)
- 支持写单个线圈(功能码05)和写单个寄存器(功能码06)
- 地址计算：实际地址 = 通道号 + do_addr偏移
- 支持动态切换功能码（通过通道250）
- 通过`SetDeviceDO`函数设置
- 异步写入队列，不阻塞主线程

## 性能优化

- ✅ 无无意义等待，CPU利用率高
- ✅ 时间完全可控，易于调优
- ✅ 逻辑简单清晰，维护性好

**性能对比**：

| 配置 | 轮询周期 | 刷新率 | 工作效率 |
|------|---------|--------|---------|
| poll=100, cmd=10 | 130ms | 7.7Hz | 15.4% |
| poll=50, cmd=5 | 65ms | 15.4Hz | 30.8% |
| poll=10, cmd=5 | 25ms | 40Hz | 80% |

### 调优建议


```ini
poll_interval_ms=500

```

## 注意事项与最佳实践

### 1. AI配置最佳实践 ✨

**优先使用最简配置**：
- ✅ **推荐**：`ai_channel = 0x0000, uint16`（90%场景）
- ❌ **不推荐**：`ai_channel = 0x0000, uint16, 1.0, AB, 0x04`（冗余参数）

**只指定必要的参数**：
- ✅ **推荐**：`ai_channel = 0x0000, int16, 0.1`（需要缩放时）
- ❌ **不推荐**：`ai_channel = 0x0000, int16, 0.1, AB, 0x04`（不必要的默认值）

**32位小端序必须明确指定**：
- ✅ **正确**：`ai_channel = 0x1000, float32, 1.0, BA`
- ❌ **错误**：`ai_channel = 0x1000, float32`（默认AB大端序，数据会错误！）

**编码器 fixed16_16 精度保留** ⭐：
- ✅ **推荐**：`ai_channel = 0x0000, fixed16_16, 1000.0`（mm转μm，保留3位小数）
- ❌ **不推荐**：`ai_channel = 0x0000, fixed16_16`（输出到short丢失小数部分）
- 📝 **说明**：fixed16_16 自动除以65536，结果为小数（如7.678），输出到short时小数部分会丢失

**多通道保持一致性**：
```ini
# ✅ 推荐 - 风格统一
ai_channel_0 = 0x0000, uint16, 0.1
ai_channel_1 = 0x0010, uint16, 0.1
ai_channel_2 = 0x0020, uint16, 0.1

# ❌ 不推荐 - 风格混乱
ai_channel_0 = 0x0000, uint16, 0.1
ai_channel_1 = 0x0010, uint16, 0.1, AB, 0x04
ai_channel_2 = 0x0020, uint16, 0.1
```

### 2. 断线检测配置最佳实践 🛡️

**根据网络质量调整阈值**：
- ✅ **稳定网络**：`max_consecutive_failures=2`（快速检测，200-400ms）
- ✅ **普通网络**：`max_consecutive_failures=3`（默认，平衡误判和检测速度）
- ✅ **不稳定网络**：`max_consecutive_failures=5`（降低误判，1-1.5秒）

**快速响应场景**：
```ini
# 编码器、运动控制等需要快速检测断线的场景
poll_interval_ms=10
timeout_ms=50
max_consecutive_failures=2
# 断线检测时间 ≈ 2 × (50 + 10) = 120ms
```

**稳定性优先场景**：
```ini
# 环境监测、数据记录等允许较长检测时间的场景
poll_interval_ms=100
timeout_ms=200
max_consecutive_failures=5
# 断线检测时间 ≈ 5 × (200 + 100) = 1500ms
```

**串口设备建议**：
```ini
# RTU串口通信相对不稳定，建议适当提高阈值
max_consecutive_failures=4
```

**TCP设备建议**：
```ini
# TCP网络相对稳定，可以降低阈值快速检测
max_consecutive_failures=2
```

### 3. 地址格式
- ✅ 所有地址均使用16进制格式(0x前缀)
- ✅ 寄存器地址范围需在设备允许范围内

### 3. 连接共享
- ✅ 相同连接参数的设备会自动共享物理连接
- ✅ 提高效率，减少资源占用

### 4. 线程安全
- ✅ 模块内部使用互斥锁确保线程安全
- ✅ 支持多设备并发访问

### 5. 数据溢出保护
- ✅ AI数据自动限制在`-32768~32767`范围内
- ✅ 建议使用缩放系数将数据缩放到合适范围

### 6. 字节序确认
- ✅ 16位数据(uint16, int16)：无需关心字节序
- ⚠️ 32位数据(uint32, int32, float32, fixed16_16)：务必确认设备字节序
- ✅ 默认AB(大端序)适用于大部分设备（约70-80%）
- ⚠️ 小端序设备必须明确指定BA

### 7. fixed16_16 数据类型识别 ⭐
**使用条件**（满足任一即可）：
- ✅ 设备手册明确说明："整数部分+小数部分"
- ✅ 设备手册说明："除以65536得到实际值"
- ✅ 设备手册说明："Q16.16格式"
- ✅ 示例数据验证：`0x0007ADA7 → 7.678`, `0x8007ADA7 → -7.678`

**常见设备**：
- 海德汉编码器、多摩川编码器、部分国产编码器

**配置技巧**：
```ini
# 基础配置
ai_channel = 0x0000, fixed16_16

# 保留精度（mm → μm）
ai_channel = 0x0000, fixed16_16, 1000.0

# 小端序设备
ai_channel = 0x0000, fixed16_16, 1.0, BA
```

### 8. 性能调优
- 根据实际需求调整`poll_interval_ms`和`command_interval_ms`
- 平衡刷新率和设备负载

### 9. 断线重连机制 🛡️
- ✅ 自动检测断线（基于`max_consecutive_failures`配置）
- ✅ **智能失败判定**：只有全部读取失败才计数，部分成功不计入失败 🎯
- ✅ 自动尝试重连（每5秒一次）
- ✅ 断线时自动清空写队列，避免积压
- ✅ 断线时`GetDeviceAD/DI`返回0（无新数据）
- ✅ 重连成功后自动恢复正常工作
- 📝 **详细说明**: 参见`RECONNECTION_MECHANISM.md`

**失败判定逻辑说明**：
```
场景1：配置了DI + 3个AI通道
- DI读取失败，AI全部成功 → 不计入失败（有成功）✅
- DI读取成功，部分AI失败 → 不计入失败（有成功）✅
- DI和AI全部失败 → 计入失败 +1 ⚠️

场景2：只配置了AI
- 部分AI成功，部分失败 → 不计入失败（有成功）✅
- 全部AI失败 → 计入失败 +1 ⚠️

优势：降低误判率，容忍部分通道偶发错误
```

## 调试建议

### 基本检查清单
1. ✅ 验证连接参数（串口号、波特率、IP地址、端口）
2. ✅ 确认从机地址设置正确
3. ✅ 检查功能码是否与设备支持的功能匹配
4. ✅ 验证寄存器地址范围
5. ✅ 确认数据类型和字节序（32位数据特别注意）

### 常见问题排查

**问题1：无法连接设备**
- 检查物理连接和驱动
- 验证IP地址和端口（TCP）
- 验证串口号和波特率（RTU）

**问题2：读取数据为0或错误**
- 确认寄存器地址正确
- 检查功能码是否支持
- 验证数据类型和字节序

**问题3：数据跳变或不稳定**
- 增大`command_interval_ms`
- 增大`timeout_ms`
- 检查网络或串口稳定性

**问题4：刷新率太低**
- 减小`poll_interval_ms`
- 减小`command_interval_ms`
- 减少读取的寄存器数量

**问题5：32位数据错误**
- ⚠️ 检查字节序配置（AB或BA）
- ⚠️ 小端序设备必须明确指定BA
- ✅ 使用设备文档确认字节序

**问题6：编码器数据不正确（fixed16_16）** ⭐
- ⚠️ 确认设备是否使用Q16.16格式（查看手册）
- ⚠️ 检查字节序（AB或BA）
- ⚠️ 验证示例值：`0x0007ADA7` 应解析为 `7.678`
- ✅ 使用缩放保留精度：`fixed16_16, 1000.0`（mm→μm）
- 📚 查看详细文档：`FIXED16_16_SUPPORT.md`

**问题7：频繁误判断线**
- ⚠️ 增大`max_consecutive_failures`（如从3改为5）
- ⚠️ 检查网络稳定性或串口质量
- ⚠️ 增大`timeout_ms`，给设备更多响应时间

**问题8：断线检测太慢**
- ✅ 减小`max_consecutive_failures`（如从5改为2）
- ✅ 减小`timeout_ms`和`poll_interval_ms`
- 📝 计算公式：检测时间 ≈ max_consecutive_failures × (timeout_ms + poll_interval_ms)
